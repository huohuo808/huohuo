第二周作业交付 · 证目

产品：证目

一句话：帮诉讼律师把证据目录里的「证明目的」写得简洁、可核对、可溯源；律师终审，不做一键可上庭文书。

一、问题与用户

目标用户：民商事诉讼主办律师（主）；助理/实习生出初稿（次）。MVP 不做当事人自助出文书、不做法院内网。

典型场景（2）

  1. 举证前编证据目录：证明目的要短句、绑日期/金额，通用 AI 写「像一坨」、引用常错。
  2. 客户甩来 AI 稿：律师要核验引用、改简洁、对照修订后终审。

核心痛点：证明目的质量差 → 幻觉/瞎编法条 → 文书不能直接用 → 专业库贵、账号摩擦。

底线：AI 不能替人担责；不做「一键可上庭」。

二、市场与机会

竞品 / 替代（≥2）

类型代表问题
通用 AI豆包 / DeepSeek能写但不简洁、幻觉重
办公 AIworkbuddy习惯「对照修改稿 + 人审」，可借鉴
专业库法宝 / 威科检索可信但贵、体验旧，不解决「写成证明目的短句」
法律 AI法天使更准，但席位/抢登摩擦

差异化切入：只做证据目录「证明目的」：事实绑定短句 + 引用可核验（待核/已核）+ 对照修订 + 律师点确认才定稿。

三、需求与范围

优先级

级需求
P0证据组导入（含摄像头扫描）→ 生成证明目的短句；引用待核/已核；对照修订；律师确认；简易导出
P0证据 ↔ 待证事实对齐
P1脱敏、原文核对、目录骨架导出、对方证据三性质证草稿
P2复杂案时间线、录音转写、类案策略

主流程：建案 → 导入/扫描证据 → 待证事实 → 生成 → 核验(待核) → 对照修订 → 律师确认 → 导出贴模板

不做：一键起诉状/答辩状可上庭；AI 直接改卷宗原文；全案材料自动整理当主卖点。
